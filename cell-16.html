১. Modeling স্ক্রিপ্ট (Python)

নিচের কোড Path loss, Shannon capacity, Erlang-B ও cluster size হিসাব করে। আমি এটি চালিয়ে যাচাই করেছি: ফলাফল যথাক্রমে 103.58 dB, 133.2 Mbps, 0.0365, 7।

import math

def fspl_db(d_km, f_mhz):
return 32.45 + 20*math.log10(d_km) + 20*math.log10(f_mhz)

def shannon(bw_hz, snr_db):
snr = 10**(snr_db/10)
return bw_hz * math.log2(1 + snr)

def erlang_b(traffic, channels):
b = 1.0
for n in range(1, channels + 1):
b = (traffic * b) / (n + traffic * b)
return b

print(fspl_db(2, 1800)) # 2 km, 1800 MHz -> 103.58 dB
print(shannon(20e6, 20)) # 20 MHz, 20 dB -> 133.2 Mbps
print(erlang_b(10, 15)) # 10 Erlang, 15 ch -> 0.0365 (3.65% blocking)
print(2*2 + 2*1 + 1*1) # cluster N, i=2 j=1 -> 7

  • Erlang-B বলে, A Erlang ট্রাফিকে N channel থাকলে কত শতাংশ কল ব্লক হবে (grade of service)। রিকার্সিভ সূত্র: B(A, n) = A·B(A, n−1) / (n + A·B(A, n−1)), শুরুতে B(A, 0) = 1।

  • ফ্রিকোয়েন্সি দ্বিগুণ করলে FSPL ঠিক 6.02 dB বাড়ে (কোডে দেখো)।

৩. Configuration ও Automation

  • CLI ও SSH: Python-এর Netmiko/Paramiko দিয়ে রাউটার/সুইচে কমান্ড পাঠানো। বহু যন্ত্রে একই কনফিগ বসাতে লুপ ব্যবহার।

  • NETCONF/YANG: XML ও YANG মডেলভিত্তিক মানসম্মত কনফিগ প্রোটোকল (port 830); RESTCONF একই জিনিস HTTP/JSON-এ।

  • SNMP: যন্ত্রের অবস্থা পর্যবেক্ষণ (monitoring), যেমন CPU, interface ট্রাফিক।

  • Ansible: এজেন্ট ছাড়া, YAML playbook-ভিত্তিক স্বয়ংক্রিয় কনফিগ।

  • Open5GS-এর মতো core কনফিগ: YAML ফাইলে PLMN (MCC/MNC), TAC, DNN, UPF ঠিকানা ইত্যাদি বসানো হয়।

  • Infrastructure as Code: Docker Compose, Helm/Kubernetes দিয়ে core সার্ভিস স্থাপন।

  • Bash: লগ ফিল্টার (grep, awk), সার্ভিস রিস্টার্ট, ব্যাকআপ, cron দিয়ে নির্ধারিত কাজ।

১৬.১ কেন scripting শিখতে হয়

টেলিকমে তিন ধরনের কাজ script দিয়ে হয়: (ক) Modeling: সূত্র বসিয়ে সিস্টেমের আচরণ হিসাব করা (path loss, Erlang, SIR), (খ) Simulation: র্‌যান্ডম ঘটনা বারবার চালিয়ে ফলাফল দেখা (BER, call blocking, handover), (গ) Configuration/Automation: শত শত যন্ত্রে একই সেটিং বসানো ও লগ পড়া। তুমি Python-এ অভ্যস্ত বলে নিচের সব উদাহরণ Python-এ; MATLAB-এ সমান ধারণা।

১৬.২ Modeling ও Simulation: চালিয়ে যাচাই করা কোড

নিচের সব ফলাফল আমি কোডটি চালিয়ে পেয়েছি।

import math, random

def erlang_b(a, n): # a = Erlang, n = channel
b = 1.0
for k in range(1, n + 1):
b = a * b / (k + a * b)
return b

def channels_needed(a, gos): # নির্দিষ্ট blocking-এর জন্য কত channel
n = 1
while erlang_b(a, n) > gos:
n += 1
return n

def sir_db(n_cluster, exponent=4, interferers=6):
q = math.sqrt(3 * n_cluster) # q = D/R
return 10 * math.log10(q ** exponent / interferers)

def q_func(x):
return 0.5 * math.erfc(x / math.sqrt(2))

def bpsk_ber_mc(ebn0_db, nbits=400000, seed=1):
random.seed(seed)
ebn0 = 10 ** (ebn0_db / 10)
sigma = math.sqrt(1 / (2 * ebn0))
err = 0
for _ in range(nbits):
bit = random.getrandbits(1)
s = 1 if bit else -1
r = s + random.gauss(0, sigma)
if (r > 0) != bool(bit):
err += 1
return err / nbits

print(channels_needed(10, 0.02)) # 17
print(round(erlang_b(10, 18), 4)) # 0.0071
for n in (3, 4, 7, 12):
print(n, round(sir_db(n), 2)) # 11.30, 13.80, 18.66, 23.34 dB
for e in (4, 6):
th = q_func(math.sqrt(2 * 10 ** (e / 10)))
print(e, round(th, 5), round(bpsk_ber_mc(e), 5))

ফলাফল ও ব্যাখ্যা:

পরিমাপ ফলাফল বোঝার বিষয়
10 Erlang ট্রাফিক, 2% blocking 17 channel স্থির কলে প্রয়োজনীয় channel-সংখ্যা (বেশি গেলে blocking কমে)
10 Erlang, 18 channel 0.0071 (0.71%) channel একটি বাড়লে blocking অনেক কমে যায়
SIR, N = 3, 4, 7, 12 (পথ সূচক 4) 11.30, 13.80, 18.66, 23.34 dB cluster বড় হলে SIR বাড়ে
BPSK BER, Eb/N0 = 4 dB তত্ত্ব 0.01250, simulation 0.01249 দুটো সর্বদা মিলে যায়, বেশি bit নিলে আরও মিলে
BPSK BER, Eb/N0 = 6 dB তত্ত্ব 0.00239, simulation 0.00232 উচ্চ SNR-এ BER অনেক কম

Monte Carlo-র ধারণা: তত্ত্বীয় সূত্র না থাকলে সম্ভাব্য সবকিছু র্‌যান্ডমভাবে নিয়ে বহুবার চালিয়ে গড় নেওয়া হয়। পরীক্ষায় জিজ্ঞাসা আসতে পারে: "কেন বেশি bit সিমুলেট করলে ফল ভালো হয়?" → কারণ নমুনা বাড়লে গড় তত্ত্বের কাছাকাছি যায় (law of large numbers)।

১৬.৩ Link budget script

import math
def fspl(d_km, f_mhz):
return 32.45 + 20*math.log10(d_km) + 20*math.log10(f_mhz)

loss = fspl(1.0, 2100) # 98.89 dB
prx = 43 + 17 + 0 - 2 - loss # Ptx 43 dBm, Gtx 17 dBi, Grx 0, cable 2 dB
print(round(loss, 2), round(prx, 2), round(prx + 100, 2))
# 98.89 dB, -40.89 dBm, fade margin (vs -100 dBm sensitivity) 59.11 dB

অর্থাৎ 1 km দূরত্বে free-space-এ সিগন্যাল খুব শক্তিশালী। বাস্তবে বাধা, বাড়ির ভেতরের loss ও fading থাকায় এত বেশি margin পাওয়া যায় না (এখানে free-space ধরা হয়েছে)।

Discrete-event vs Monte Carlo: discrete-event-এ সময়ের সাথে ঘটনা (কল আসা, কল শেষ) একটি event queue-এ রেখে ক্রমানুসারে চালানো হয় (যেমন call blocking সিমুলেশন, ns-3); Monte Carlo-তে সময়ের ক্রম না থাকলেও চলে (যেমন BER সিমুলেশন)।

১৬.৫ Configuration ও automation

কেন: ১০০টি router-এ হাতে একই কনফিগ বসানো সময়সাপেক্ষ ও ভুলপ্রবণ। script দিয়ে template থেকে কনফিগ বানিয়ে সব যন্ত্রে পাঠানো হয়।

প্রোটোকল/টুল কাজ বৈশিষ্ট্য
SSH + CLI (Netmiko/Paramiko) কমান্ড পাঠানো সহজ, পুরনো যন্ত্রেও চলে, কিন্তু আউটপুট text পার্স করতে হয়
SNMP পর্যবেক্ষণ (CPU, interface counter) UDP 161/162
NETCONF + YANG মানসম্মত কনফিগ XML, port 830, transaction/rollback সমর্থন
RESTCONF NETCONF-এর HTTP/JSON রূপ REST API
gNMI streaming telemetry gRPC, আধুনিক পর্যবেক্ষণ
Ansible স্বয়ংক্রিয় কনফিগ এজেন্টবিহীন, YAML playbook, idempotent
Docker Compose / Helm (Kubernetes) core সার্ভিস স্থাপন IaC, 5GC ডিপ্লয়মেন্ট

Idempotent মানে: একই script বারবার চালালেও শেষ অবস্থা একই থাকে, ডাবল কনফিগ হয় না।

কনফিগ template থেকে সব যন্ত্রের কনফিগ বানানো (আমি চালিয়ে দেখিনি, শুধু কাঠামোর ধারণা):

devices = [
{"name": "bts-mirpur-01", "ip": "10.10.1.11", "vlan": 110},
{"name": "bts-uttara-02", "ip": "10.10.1.12", "vlan": 120},
]
template = """hostname {name}
interface vlan {vlan}
ip address {ip} 255.255.255.0
"""
for d in devices:
print(template.format(**d)) # প্রতিটি যন্ত্রের আলাদা কনফিগ তৈরি

Netmiko দিয়ে পাঠানোর কাঠামো (যন্ত্র লাগে বলে এখানে চালাইনি):

from netmiko import ConnectHandler
conn = ConnectHandler(device_type="cisco_ios", host="10.10.1.11",
username="admin", password="***")
output = conn.send_config_set(["interface vlan 110", "ip address 10.10.1.11 255.255.255.0"])
conn.disconnect()

5G core কনফিগ (Open5GS-এর মতো, YAML): PLMN (MCC=470 বাংলাদেশের জন্য MCC), MNC, TAC, DNN, UPF-এর ঠিকানা, slice-এর SST/SD ইত্যাদি লেখা হয়। পরীক্ষায় জিজ্ঞাসা আসতে পারে কোন প্রোটোকল/টুল কোন কাজে।

Bash লগ ও মেইনটেন্স:

  • grep -i "error" /var/log/messages | tail — শেষ ত্রুটিগুলো দেখা
