Cellular Topic 13: Mobile User Data Management ও Authentication

Theory • সহজ সারাংশ + বিস্তারিত নোট

মোবাইল নেটওয়ার্ক প্রতিটি সাবস্ক্রাইবারের তথ্য নিরাপদে রাখে এবং সংযোগের আগে তার পরিচয় যাচাই করে। পরিচয়ের ভিত্তি SIM/USIM কার্ডে থাকা গোপন কী Ki (বা LTE/5G-তে K), যেটি কার্ড ও নেটওয়ার্কের ডেটাবেস (AuC/HSS/UDM) ছাড়া আর কোথাও যায় না।

সাবস্ক্রাইবার ডেটা (profile)-তে যা থাকে

  • পরিচয়: IMSI, MSISDN, secret key Ki/K।

  • সেবা: অনুমোদিত সেবার তালিকা (voice, SMS, data, roaming অনুমতি)।

  • ডেটা সেশন: অনুমোদিত APN/DNN, QoS প্রোফাইল (AMBR, QCI/5QI)।

  • অবস্থান: বর্তমান MME/VLR/AMF-এর ঠিকানা।

  • চার্জিং: প্রিপেইড/পোস্টপেইড, অনলাইন চার্জিং (OCS) ও CDR (Call Detail Record) তৈরির তথ্য।

GSM Authentication (একমুখী)

  1. নেটওয়ার্ক একটি র‍্যান্ডম সংখ্যা RAND পাঠায়।

  2. SIM Ki ও RAND দিয়ে A3 অ্যালগরিদমে SRES বানিয়ে ফেরত দেয়; নেটওয়ার্কও একই গণনা করে মেলায়।

  3. A8 দিয়ে সিফার কী Kc তৈরি, A5 (A5/1, A5/3) দিয়ে রেডিও এনক্রিপশন।

  • নেটওয়ার্ক ইউজারকে যাচাই করে, কিন্তু ইউজার নেটওয়ার্ককে নয়, ফলে নকল base station (IMSI catcher) ঝুঁকি থাকে। এক সেট (RAND, SRES, Kc) = triplet।

3G/4G Authentication (পারস্পরিক, AKA)

  • Authentication vector (4G-তে): RAND, AUTN, XRES, KASME।

  • UE AUTN যাচাই করে নেটওয়ার্ককে বিশ্বাস করে, তারপর RES পাঠায়; নেটওয়ার্ক RES-কে XRES-এর সাথে মেলায়। দুই পক্ষই একে অপরকে যাচাই করে (mutual authentication)।

  • অ্যালগরিদম সেট: Milenage (বা TUAK)।

  • কী হায়ারার্কি: K → CK, IK → KASME → NAS কী ও KeNB → রেডিও কী।

  • 4G এনক্রিপশন/ইন্টিগ্রিটি: EEA/EIA (SNOW 3G, AES, ZUC); প্রতিটি সিগন্যালিংয়ে ইন্টিগ্রিটি সুরক্ষা বাধ্যতামূলক।

5G Authentication

  • দুটি পদ্ধতি: 5G-AKA ও EAP-AKA'। নোড: UE, AMF/SEAF, AUSF, UDM/ARPF।

  • SUCI: স্থায়ী পরিচয় SUPI/IMSI এনক্রিপ্ট করে (ইউজারের কাছে থাকা হোম নেটওয়ার্কের public key দিয়ে) পাঠানো হয়, তাই IMSI catcher আর IMSI পড়তে পারে না।

  • 5G এনক্রিপশন/ইন্টিগ্রিটি: NEA/NIA।

  • Home নেটওয়ার্ক roaming-এও চূড়ান্ত authentication ফলাফল নিশ্চিত করে।

সম্ভাব্য MCQ

  • GSM-এ authentication-এ নেটওয়ার্ক যে র‍্যান্ডম সংখ্যা পাঠায়? → RAND

  • SIM-এর গোপন কী কী নামে পরিচিত? → Ki (K)

  • GSM-এ authentication কোন অ্যালগরিদমে হয়? → A3

  • 5G-তে IMSI গোপন রাখার ব্যবস্থা? → SUCI

  • 4G AKA-তে ইউজার নেটওয়ার্ককে যাচাই করে কোন প্যারামিটার দিয়ে? → AUTN

বিস্তারিত নোট

১৩.১ ইউজার পরিচয় ও ডেটার ধরন

  • IMSI: সর্বোচ্চ 15 ডিজিট = MCC (3) + MNC (2–3) + MSIN। বাংলাদেশের MCC = 470। (MNC-এর নির্দিষ্ট মান অপারেটর অনুযায়ী; ব্যক্তিগতভাবে মিলিয়ে নেবেন।)

  • MSISDN: ফোন নম্বর (E.164, যেমন +880 1X XXXX XXXX)।

  • IMEI: ডিভাইসের পরিচয়, 15 ডিজিট (TAC + সিরিয়াল + check digit)। IMEISV-তে 16 ডিজিট।

  • TMSI / P-TMSI / GUTI / 5G-GUTI: IMSI গোপন রাখতে অস্থায়ী পরিচয়।

  • SUPI / SUCI (5G): SUPI স্থায়ী পরিচয় (IMSI-এর মতো); SUCI হলো SUPI-কে হোম নেটওয়ার্কের public key দিয়ে এনক্রিপ্ট করা রূপ, যাতে IMSI-catcher ধরতে না পারে।

  • SIM/USIM-এ থাকে: IMSI, গোপন কী Ki (K), অ্যালগরিদম (MILENAGE ইত্যাদি), PIN/PUK। Ki কখনো SIM-এর বাইরে যায় না; অপারেটরের AuC-তেও একই Ki থাকে।

১৩.২ GSM Authentication (Triplet)

  1. VLR/MSC HLR/AuC-র কাছ থেকে triplet (RAND, SRES, Kc) নেয়।

  2. নেটওয়ার্ক UE-কে RAND (128 বিট র‍্যান্ডম) পাঠায়।

  3. SIM A3 অ্যালগরিদম দিয়ে (Ki, RAND) থেকে SRES (32 বিট) এবং A8 দিয়ে Kc (64 বিট সেশন কী) বের করে।

  4. UE SRES ফেরত পাঠায়; নেটওয়ার্ক নিজের SRES-এর সাথে মেলায়।

  5. রেডিওতে A5 অ্যালগরিদম (A5/1, A5/2, A5/3) Kc দিয়ে এনক্রিপশন।

GSM-এর দুর্বলতা: শুধু ইউজার নেটওয়ার্ককে যাচাই করায়, নেটওয়ার্ক ইউজারের কাছে নিজেকে প্রমাণ করে না ⇒ ভুয়া base station (IMSI catcher) সম্ভব। A5/1 ভাঙা গেছে, A5/2 দুর্বল। ইন্টেগ্রিটি সুরক্ষা নেই।

১৩.৩ UMTS/LTE AKA (পারস্পরিক authentication)

  • HSS/AuC authentication vector তৈরি করে: RAND, AUTN, XRES, CK, IK (LTE-তে CK, IK থেকে KASME)।

  • AUTN (SQN, AMF, MAC) থাকায় UE নেটওয়ার্ককে যাচাই করে (পারস্পরিক authentication) এবং SQN দিয়ে replay ঠেকায়।

  • UE RES পাঠায়; নেটওয়ার্ক XRES-এর সাথে মেলায়।

  • LTE কী-ক্রম (hierarchy): K → CK, IK → KASME → KNASenc, KNASint, KeNB → KRRCenc, KRRCint, KUPenc।

  • LTE এনক্রিপশন অ্যালগরিদম: EEA1 (SNOW 3G), EEA2 (AES), EEA3 (ZUC); ইন্টেগ্রিটি: EIA1/2/3। সিগন্যালিং-এ এনক্রিপশন ও ইন্টেগ্রিটি দুটোই, ইউজার ডেটায় এনক্রিপশন।

১৩.৪ 5G Authentication

উপাদান: AMF/SEAF (anchor), AUSF, UDM/ARPF, SIDF (SUCI→SUPI ডিক্রিপশন)।

  • 5G-AKA ও EAP-AKA' দুই পদ্ধতি।

  • Home Network Control: হোম নেটওয়ার্ক (AUSF) চূড়ান্ত নিশ্চিত করে ইউজার সত্যিই authenticate হয়েছে (ভিজিটেড নেটওয়ার্কের ওপর নির্ভর না করে)।

  • কী-ক্রম: K → CK/IK → KAUSF → KSEAF → KAMF → KNASenc/int, KgNB → KRRC, KUP।

  • NEA1/2/3, NIA1/2/3 অ্যালগরিদম (128-বিট; NEA2/NIA2 = AES)।

  • নতুন: SUCI দিয়ে পরিচয় সুরক্ষা; ইউজার প্লেনেও ইন্টেগ্রিটি সুরক্ষা (ঐচ্ছিক); আরও শক্ত রোমিং নিরাপত্তা (SEPP)।

১৩.৫ তুলনা

বিষয় GSM UMTS/LTE 5G
Authentication একমুখী পারস্পরিক (AKA) পারস্পরিক (5G-AKA/EAP-AKA')

পরিচয় সুরক্ষা TMSI TMSI/GUTI SUCI (এনক্রিপ্টেড)

১৩.৬ অন্যান্য নিরাপত্তা ধারণা

  • SIM swap, SS7 হামলা, IMSI catcher, DoS — সাধারণ হুমকি।

  • IPsec (S1/X2/N2/N3 সুরক্ষা), SEPP (5G রোমিং সীমানায়), Firewall/SBC।

  • CEIR/EIR: চুরি যাওয়া/অবৈধ IMEI ব্লক। বাংলাদেশে BTRC-র মোবাইল ডিভাইস নিবন্ধন (এই তথ্য স্মৃতি-নির্ভর; হালনাগাদ যাচাই করুন)।

১৩.৭ অনুশীলন

  1. GSM-এ RAND কত বিট? → 128; SRES 32; Kc 64।

  2. UE নেটওয়ার্ককে যাচাই করে কোন উপাদান দিয়ে? → AUTN।

  3. SUCI কী? → SUPI-র এনক্রিপ্টেড রূপ (হোম নেটওয়ার্কের public key দিয়ে)।

  4. LTE-তে AES-ভিত্তিক এনক্রিপশন? → EEA2।

  5. Ki কোথায় থাকে? → SIM ও AuC-তে; বাইরে যায় না।
