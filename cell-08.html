Topic 8: 5G Network Slicing5G Network Slicing

Theory • সহজ সারাংশ + বিস্তারিত নোটTheory • short note + detailed note

🧠 সংক্ষেপ নোটShort note

Network slicing মানে একটি ভৌত 5G নেটওয়ার্কের ভেতরে একাধিক আলাদা "লজিক্যাল নেটওয়ার্ক" বানানো, প্রতিটি আলাদা কাজের জন্য সাজানো।Network slicing means creating several separate "logical networks" inside one physical 5G network, each tuned for a different job.

  • eMBB = বেশি গতি (ভিডিও)। URLLC = খুব কম দেরি ও নির্ভরযোগ্য। mMTC = অনেক ছোট IoT device।eMBB = high speed (video). URLLC = very low delay and reliable. mMTC = many small IoT devices.
  • S-NSSAI = slice-এর পরিচয় = SST (ধরন) + ঐচ্ছিক SD। SST 1 = eMBB, 2 = URLLC, 3 = MIoT, 4 = V2X।S-NSSAI = slice identity = SST (type) + optional SD. SST 1 = eMBB, 2 = URLLC, 3 = MIoT, 4 = V2X.
  • NSSAI: ফোন Requested NSSAI পাঠায়, নেটওয়ার্ক Allowed NSSAI ফেরত দেয়।NSSAI: the phone sends a Requested NSSAI, the network returns an Allowed NSSAI.
  • NSSF slice বেছে দেয়।NSSF selects the slice.
  • Enabler: NFV + SDN + cloud-native।Enabler: NFV + SDN + cloud-native.
  • IMT-2020 লক্ষ্য: peak 20 Gbps (DL), 1 ms latency, 10⁶ device/km²।IMT-2020 targets: 20 Gbps peak (DL), 1 ms latency, 10⁶ devices/km².

🧠 মনে রাখার কৌশল:Memory trick: 3টি slice = ভিডিও (eMBB, গতি), গাড়ি (URLLC, দেরি), সেন্সর (mMTC, সংখ্যা)। গতি-দেরি-সংখ্যা।3 slices = video (eMBB, speed), car (URLLC, delay), sensors (mMTC, count). Speed-delay-count.

৮.১ কেন slice লাগে8.1 Why slices are needed

🛵 উপমা:Analogy: একটি বড় হাইওয়েকে লেনে ভাগ করার মতো: অ্যাম্বুলেন্স লেন (URLLC), বাস লেন (eMBB), আর ছোট সাইকেল লেন (mMTC)। একই রাস্তা, কিন্তু আলাদা নিয়ম ও আলাদা গতি।Like dividing one highway into lanes: an ambulance lane (URLLC), a bus lane (eMBB) and a small bicycle lane (mMTC). Same road, different rules and speeds.

৮.২ S-NSSAI ও NSSAI8.2 S-NSSAI and NSSAI
S-NSSAI গঠনS-NSSAI structure
S-NSSAI = SST (8 bit) + SD (24 bit, ঐচ্ছিক / optional)
SST = slice-এর ধরন (1, 2, 3, 4...), SD = একই ধরনের আলাদা slice চিনতে।SST = slice type (1, 2, 3, 4...), SD = tells apart slices of the same type.
  1. ফোন Registration-এর সময় Requested NSSAI পাঠায়: "আমার এই slice গুলো লাগবে"।During Registration the phone sends a Requested NSSAI: "I need these slices".
  2. AMF/NSSF ইউজারের সাবস্ক্রিপশন ও নেটওয়ার্ক দেখে যাচাই করে।The AMF/NSSF checks the subscription and the network.
  3. নেটওয়ার্ক Allowed NSSAI ফেরত দেয়: "এগুলো পাবে"।The network returns an Allowed NSSAI: "you may use these".
৮.৩ Slice কীভাবে বানানো হয়8.3 How a slice is built
  • NFV: VNF/CNF দিয়ে slice-এর জন্য আলাদা SMF, UPF চালু।NFV: separate SMF and UPF instances for a slice using VNFs/CNFs.
  • SDN: transport network-এ slice-এর জন্য আলাদা পথ ও bandwidth।SDN: a separate path and bandwidth for the slice in the transport network.
  • RAN slicing: radio রিসোর্স (RB) slice অনুযায়ী ভাগ।RAN slicing: radio resources (RBs) shared out by slice.
  • Cloud-native: container + Kubernetes দিয়ে দ্রুত চালু ও scale।Cloud-native: containers + Kubernetes for fast start and scaling.

💡 Slice পুরোপুরি কাজ করতে 5G SA (Standalone, 5GC সহ) লাগে। NSA (Option 3x) LTE anchor ও EPC ব্যবহার করে, তাই সেখানে slicing সীমিত।Full slicing needs 5G SA (Standalone, with 5GC). NSA (Option 3x) uses an LTE anchor and EPC, so slicing is limited there.
