Topic 6: Cellular সিস্টেমে NFVNetwork Function Virtualization (NFV) in Cellular Systems

Theory • সহজ সারাংশ + বিস্তারিত নোটTheory • short note + detailed note

🧠 সংক্ষেপ নোটShort note

NFV মানে আগে যে কাজগুলো আলাদা আলাদা দামি যন্ত্রে হতো, সেগুলোকে সাধারণ server-এ চলা software বানিয়ে ফেলা। কম খরচ, দ্রুত পরিবর্তন।NFV means turning jobs that used to run on separate costly boxes into software running on ordinary servers. Lower cost, faster change.

  • VNF = একটি network function-এর software রূপ (যেমন virtual MME)।VNF = the software form of a network function (e.g. a virtual MME).
  • NFVI = সব VNF যে hardware ও virtualization-এর ওপর চলে।NFVI = the hardware and virtualization layer on which VNFs run.
  • MANO = ম্যানেজার: NFVO (সমন্বয়), VNFM (VNF-এর জীবনচক্র), VIM (hardware রিসোর্স)।MANO = the manager: NFVO (orchestration), VNFM (VNF life cycle), VIM (hardware resources).
  • VM ভারী কিন্তু আলাদা; Container (CNF) হালকা, দ্রুত চালু, Kubernetes-এ চলে।VM is heavy but isolated; a container (CNF) is light, starts fast and runs on Kubernetes.
  • SDN = control ও data আলাদা; কেন্দ্রীয় controller পুরো নেটওয়ার্ক চালায়।SDN = control and data are separate; a central controller runs the whole network.
  • DPDK / SR-IOV = VM-এর packet প্রক্রিয়া দ্রুত করার কৌশল।DPDK / SR-IOV = tricks that speed up packet handling in VMs.

🧠 মনে রাখার কৌশল:Memory trick: NFV = "বাক্স থেকে software"। MANO = তিন ম্যানেজার: Orchestrator (সবার প্রধান), VNFM (কাজের দায়িত্ব), VIM (যন্ত্রপাতির দায়িত্ব)।NFV = "from box to software". MANO = three managers: the Orchestrator (boss), the VNFM (looks after the job) and the VIM (looks after the hardware).

📖 বিস্তারিত নোটDetailed note

৬.১ সমস্যাটা কী ছিল, NFV কী সমাধান6.1 The problem and the NFV answer

🛵 উপমা:Analogy: আগে প্রতিটি কাজের জন্য আলাদা যন্ত্র কেনা মানে প্রতিটি পোশাকের জন্য আলাদা আলমারি কেনা। NFV হলো একটি বড় সাধারণ আলমারি (server) যেখানে সব পোশাক (VNF) রাখা যায়, দরকার মতো বাড়ানো-কমানো যায়।Buying a separate box for every job is like buying a separate wardrobe for each garment. NFV is one big common wardrobe (server) where all garments (VNFs) fit, and you can add or remove as needed.

  • সমস্যা: সাধারণ software network packet ধীরে প্রক্রিয়া করে।Problem: ordinary software handles network packets slowly.
  • DPDK: kernel এড়িয়ে সরাসরি NIC থেকে packet পড়ে। SR-IOV: একটি NIC-কে অনেক VM-এর কাছে আলাদা করে দেয়।DPDK: bypasses the kernel and reads packets straight from the NIC. SR-IOV: splits one NIC into separate pieces for many VMs.
৬.৪ SDN ও FCAPS6.4 SDN and FCAPS

SDN-এ router-এর "মগজ" (control plane) আলাদা হয়ে একটি কেন্দ্রীয় controller-এ যায়। router শুধু hardware (data plane) হিসেবে কাজ করে। controller OpenFlow দিয়ে নির্দেশ পাঠায়।In SDN the "brain" (control plane) of the router moves to a central controller. The router just forwards (data plane). The controller sends rules using OpenFlow.

🧠 মনে রাখার কৌশল:Memory trick: FCAPS = "ফোন কলে আপনি পিছিয়ে সরে": F-C-A-P-S। (বা শুধু প্রথম অক্ষরগুলো মুখস্থ)FCAPS = Fault, Configuration, Accounting, Performance, Security. Remember the five initials in order.

৬.৫ অনুশীলন6.5 Practice
VIM কী পরিচালনা করে?What does the VIM manage?

NFVI-এর compute, storage ও network রিসোর্স।The compute, storage and network resources of the NFVI.

Container VM-এর চেয়ে কেন দ্রুত?Why is a container faster than a VM?

Container host kernel ভাগ করে, তাই নিজস্ব OS চালু করতে হয় না।A container shares the host kernel, so no separate OS needs to boot.

FCAPS-এ A মানে কী?What is A in FCAPS?

Accounting।Accounting.

DPDK কোন সমস্যা সমাধান করে?Which problem does DPDK solve?

VM-এর packet প্রক্রিয়ার গতি (kernel bypass)।Slow packet processing in VMs (kernel bypass).

SDN-এর মূল ধারণা কী?Main idea of SDN?

Control plane ও data plane আলাদা, controller দিয়ে কেন্দ্রীয় নিয়ন্ত্রণ।Separate control and data planes with central control through a controller.
