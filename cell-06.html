Cellular Topic 6: Network Function Virtualization (NFV) in Cellular Systems

Theory • সহজ সারাংশ + বিস্তারিত নোট

NFV-এ নেটওয়ার্কের কাজ (MME, S-GW, P-GW, firewall, router ইত্যাদি) বিশেষ হার্ডওয়্যার বক্সের বদলে সাধারণ সার্ভারে সফটওয়্যার হিসেবে চালানো হয়। ফলে নতুন সেবা দ্রুত চালু করা যায়, খরচ কমে, চাহিদা অনুযায়ী স্কেল করা যায়। এর মানদণ্ড তৈরি করেছে ETSI।

NFV আর্কিটেকচারের তিন স্তম্ভ (ETSI)

  • VNF (Virtualized Network Function): সফটওয়্যার রূপে নেটওয়ার্ক ফাংশন, যেমন vEPC, vIMS, vFirewall।

  • NFVI (NFV Infrastructure): VNF চালানোর পরিকাঠামো: কম্পিউট, স্টোরেজ, নেটওয়ার্ক হার্ডওয়্যার ও তার উপর virtualization স্তর (hypervisor/container)।

  • MANO (Management and Orchestration): পুরো ব্যবস্থার পরিচালনা, তিনটি অংশে:

    • NFVO: সেবা ও রিসোর্সের সামগ্রিক orchestration।

    • VNFM: প্রতিটি VNF-এর জীবনচক্র (তৈরি, স্কেল, বন্ধ)।

    • VIM: NFVI রিসোর্স ব্যবস্থাপনা (উদাহরণ: OpenStack)।

মোবাইল নেটওয়ার্কে প্রয়োগ

  • vEPC: MME, S-GW, P-GW সফটওয়্যারে; ট্রাফিক বাড়লে instance বাড়ানো হয় (scale-out)।

  • vIMS / vRAN: voice সেবা ও baseband প্রক্রিয়াও virtualize করা যায়।

  • Cloud-native / CNF: 5G Core শুরু থেকেই container ও microservice-ভিত্তিক (Kubernetes), যাকে Cloud-native Network Function বলে।

NFV বনাম SDN

বিষয় NFV SDN
মূল ধারণা নেটওয়ার্ক ফাংশনকে হার্ডওয়্যার থেকে আলাদা করা Control plane ও data plane আলাদা করা
ফোকাস ফাংশন সফটওয়্যারে চালানো কেন্দ্রীয় প্রোগ্রামযোগ্য নিয়ন্ত্রণ
উদাহরণ vEPC, vFirewall OpenFlow, SDN controller
সম্পর্ক একে অপরের পরিপূরক, একটি ছাড়াও অন্যটি চলে

Hypervisor বনাম Container

  • Virtual Machine (VM): প্রতিটিতে পূর্ণ guest OS; আলাদা কিন্তু ভারী।

  • Container: host OS kernel ভাগ করে, হালকা ও দ্রুত চালু; Docker, Kubernetes।

  • পারফরম্যান্স বাড়াতে DPDK, SR-IOV ব্যবহার হয়, কারণ সাধারণ সার্ভারে packet প্রক্রিয়া ধীর।

সুবিধা ও চ্যালেঞ্জ

  • সুবিধা: CAPEX/OPEX কম, দ্রুত সেবা চালু, স্কেল সহজ, vendor lock-in কম।

  • চ্যালেঞ্জ: carrier-grade নির্ভরযোগ্যতা (99.999%), পারফরম্যান্স, security, orchestration-এর জটিলতা।

সম্ভাব্য MCQ

  • NFV-এর মানদণ্ড কোন সংস্থা তৈরি করেছে? → ETSI

  • NFV MANO-র কোন অংশ VNF-এর জীবনচক্র দেখে? → VNFM

  • VIM-এর একটি উদাহরণ? → OpenStack

  • SDN-এর মূল বৈশিষ্ট্য কী? → Control ও data plane আলাদা করা

  • 5G Core কোন ধরনের স্থাপত্যে বানানো? → Cloud-native, microservice-ভিত্তিক

বিস্তারিত নোট

৬.১ সমস্যা ও সমাধান

প্রচলিত টেলিকম নেটওয়ার্কে প্রতিটি কাজের জন্য আলাদা বিশেষ হার্ডওয়্যার বাক্স (router, firewall, EPC নোড, session border controller) কিনতে হতো। এর ফলে: (১) প্রতিটি নতুন সেবায় নতুন হার্ডওয়্যার ও দীর্ঘ সময়, (২) বিক্রেতা-নির্ভরতা (vendor lock-in), (৩) যন্ত্র দ্রুত অচল হয়, (৪) চাহিদা কম-বেশি হলেও ক্ষমতা স্থির। NFV সমাধান দেয়: নেটওয়ার্ক ফাংশন সফটওয়্যার হিসেবে লিখে সাধারণ উচ্চ-ক্ষমতার সার্ভারে (COTS) চালানো, ফলে একই সার্ভারে বিভিন্ন ফাংশন চলে, চাহিদা অনুযায়ী বাড়ানো-কমানো যায়, আর সফটওয়্যার আপডেট করেই নতুন সুবিধা আসে।

ইতিহাস: ২০১২ সালে বিশ্বের প্রধান অপারেটররা প্রথম white paper প্রকাশ করে এবং ETSI ISG NFV (Industry Specification Group) গঠিত হয়। মানদণ্ড ETSI GS NFV সিরিজে।

৬.২ ETSI NFV আর্কিটেকচার ফ্রেমওয়ার্ক

উপাদান বিবরণ
VNF সফটওয়্যার রূপে নেটওয়ার্ক ফাংশন (vEPC, vIMS, vFirewall, vRouter)। এক বা একাধিক VNFC (component) নিয়ে গঠিত।
NFVI VNF-এর চলার পরিকাঠামো: compute, storage, network হার্ডওয়্যার + virtualization স্তর (hypervisor/container runtime)
MANO: NFVO সেবা (Network Service) ও রিসোর্সের সামগ্রিক orchestration, একাধিক VIM জুড়ে; VNF onboarding
MANO: VNFM প্রতিটি VNF-এর জীবনচক্র: instantiate, configure, scale, heal, terminate
MANO: VIM একটি ডেটা সেন্টারের NFVI রিসোর্স নিয়ন্ত্রণ (উদাহরণ: OpenStack, Kubernetes-ভিত্তিক)
EMS VNF-এর ফাংশনাল ব্যবস্থাপনা (fault, config, performance)
OSS/BSS পরিচালনা ও ব্যবসায়িক সিস্টেম (বিলিং, অর্ডার)

Reference point (মনে রাখার মতো): Os-Ma-nfvo (OSS–NFVO), Or-Vnfm (NFVO–VNFM), Vi-Vnfm (VNFM–VIM), Or-Vi (NFVO–VIM), Ve-Vnfm (EMS/VNF–VNFM), Nf-Vi (NFVI–VIM), Vn-Nf (VNF–NFVI)।

Descriptor: VNFD (একটি VNF-এর বিবরণ: প্রয়োজনীয় CPU/RAM/storage, নেটওয়ার্ক ইন্টারফেস, স্কেলিং নীতি), NSD (পুরো সেবার বিবরণ), VNFFG (VNF Forwarding Graph: ট্রাফিক কোন কোন VNF-এর মধ্য দিয়ে যাবে, service chaining)।

৬.৩ VNF Lifecycle

  1. Onboarding: প্যাকেজ (image ও VNFD) নিবন্ধন ও যাচাই।

  2. Instantiation: রিসোর্স বরাদ্দ করে VNF চালু ও কনফিগার।

  3. Scaling: scale-out/in (instance সংখ্যা বাড়ানো/কমানো) ও scale-up/down (একই instance-এ CPU/RAM বদল)। স্বয়ংক্রিয়ভাবে লোড দেখে হয় (autoscaling)।

  4. Healing: ব্যর্থ instance সরিয়ে নতুন চালু।

  5. Update/Upgrade: সেবা না থামিয়ে (rolling upgrade)।

  6. Termination: রিসোর্স মুক্ত।

Scale-out উদাহরণ: প্রতি vEPC instance 10,000 session সামলায়। 45,000 session এলে ceil(45000/10000) = 5 instance; N+1 redundancy-তে মোট 6 instance রাখা হয়।

৬.৪ Virtualization প্রযুক্তি

বিষয় Virtual Machine (VM) Container
বিচ্ছিন্নতা পূর্ণ (প্রতিটির নিজস্ব guest OS) প্রসেস-স্তরের (host kernel ভাগ)
আকার ও চালু হওয়ার সময় বড় (GB), মিনিট হালকা (MB), সেকেন্ড
ঘনত্ব কম বেশি
নিরাপত্তা বেশি কম (kernel ভাগ)
টুল KVM, VMware ESXi, Xen Docker, containerd, Kubernetes

  • Hypervisor Type 1 (bare-metal): সরাসরি হার্ডওয়্যারের উপর (KVM, ESXi, Xen); টেলিকমে প্রচলিত। Type 2: host OS-এর উপর (VirtualBox)।

  • CNF (Cloud-native Network Function): microservice ও container-ভিত্তিক VNF; Kubernetes-এ চলে; 5G core মূলত CNF।

  • Kubernetes ধারণা: Pod (সবচেয়ে ছোট একক), Deployment, Service, ConfigMap; স্বয়ংক্রিয় স্কেলিং ও পুনরুদ্ধার।

OpenStack (VIM-এর জনপ্রিয় উদাহরণ): Nova (compute), Neutron (network), Cinder (block storage), Glance (image), Keystone (identity), Swift (object storage), Heat (orchestration), Horizon (dashboard)।

ওপেন সোর্স উদ্যোগ: OPNFV (ইন্টিগ্রেশন), ONAP (orchestration), Open Source MANO (OSM), OpenDaylight/ONOS (SDN controller)।

৬.৫ পারফরম্যান্স সমস্যা ও সমাধান

সাধারণ সার্ভারে Linux kernel দিয়ে packet প্রক্রিয়া ধীর (interrupt ও copy ওভারহেড)। সমাধান:

  • DPDK: user-space-এ poll-mode driver, kernel ও interrupt এড়িয়ে সরাসরি NIC থেকে packet; মিলিয়ন packet/s।

  • SR-IOV: একটি ভৌত NIC-কে অনেক virtual function-এ ভাগ করে VM-কে সরাসরি দেয়।

  • PCI passthrough, hugepages, CPU pinning, NUMA-aware placement latency ও jitter কমায়।

  • SmartNIC/FPGA offload: ভারী কাজ হার্ডওয়্যারে।

৬.৬ SDN বনাম NFV

বিষয় SDN NFV
ফোকাস Control plane ও data plane আলাদা, কেন্দ্রীয় প্রোগ্রামযোগ্য নিয়ন্ত্রণ ফাংশনকে হার্ডওয়্যার থেকে আলাদা
প্রোটোকল OpenFlow, NETCONF, P4 মূলত ETSI মানদণ্ড, API
নিয়ন্ত্রক SDN controller (ONOS, OpenDaylight) MANO
উদাহরণ ডেটা সেন্টার ফ্যাব্রিক, WAN ট্রাফিক প্রকৌশল vEPC, vIMS, vFirewall

SDN-এর ইন্টারফেস: Northbound (controller–অ্যাপ), Southbound (controller–সুইচ, OpenFlow)। দুটি স্বাধীন, কিন্তু একসাথে শক্তিশালী: SDN ট্রাফিককে VNF-গুলোর মধ্য দিয়ে ঘুরিয়ে service chaining করে।

৬.৭ টেলিকমে ব্যবহার ও Telco Cloud

  • vEPC/5GC: স্বয়ংক্রিয় স্কেলিং, ঘটনা-ভিত্তিক (কনসার্ট, ঈদে ট্রাফিক বৃদ্ধি) ক্ষমতা।

  • vIMS: VoLTE/VoWiFi core সফটওয়্যারে।

  • vRAN/Cloud RAN: baseband সফটওয়্যারে।

  • vCPE, vFirewall, vLoad balancer: গ্রাহকের প্রান্তের ডিভাইসের ফাংশন ক্লাউডে।

  • Telco cloud স্তর: Central DC (control, ডেটাবেস), Regional DC, Edge (UPF, MEC, vRAN)। latency-সংবেদনশীল সেবা edge-এ।

সুবিধা: কম CAPEX/OPEX, দ্রুত time-to-market, স্কেলযোগ্যতা, কম vendor lock-in, স্বয়ংক্রিয়তা।

চ্যালেঞ্জ: carrier-grade 99.999% নির্ভরযোগ্যতা, পারফরম্যান্স ও latency, বহু বিক্রেতার VNF একসাথে (interoperability), নিরাপত্তা (hypervisor আক্রমণ), orchestration-এর জটিলতা, দক্ষ জনবল।

৬.৮ অনুশীলন

  1. ETSI NFV-তে VNF-এর জীবনচক্র দেখে কোন MANO উপাদান? → VNFM।

  2. VIM-এর একটি উদাহরণ? → OpenStack।

  3. OpenStack-এর compute সার্ভিস? → Nova।

  4. DPDK-এর কাজ? → user-space-এ দ্রুত packet প্রক্রিয়া, kernel এড়িয়ে।

  5. CNF কী? → container/microservice-ভিত্তিক cloud-native network function।
